# 手机版插件格式（`.dshp`）

一个 `.dshp` 就是一个 zip。目标是**桌面和手机同构**：T0 插件两边都能装。

```
sample-battery.dshp
├── manifest.json
├── tools/
│   └── battery_history.json      # JSON Schema，形状与 DeepSeek tools[].function.parameters 一致
├── skills/
│   └── battery.md                # 追加进上下文的正文（渐进披露）
├── code/
│   └── main.js                   # 仅 T1
└── code/classes.dex              # 仅 T2
```

## manifest.json

```json
{
  "id": "com.example.battery",
  "name": "电量历史",
  "version": "0.1.0",
  "tier": "declarative",
  "minApp": "0.1",
  "capabilities": ["shell.readonly"],
  "tools": [
    {
      "name": "battery_history",
      "schema": "tools/battery_history.json",
      "impl": { "kind": "shell", "command": "dumpsys battery" }
    }
  ],
  "skills": [{ "name": "battery", "path": "skills/battery.md" }],
  "ui": [{ "slot": "settings.section", "title": "电量历史" }]
}
```

字段含义（**只有这几个，不要再加**）：

| 字段 | 说明 |
|---|---|
| `tier` | `declarative` / `script` / `native` —— 决定装载时弹什么颜色的警告 |
| `capabilities` | 请求的能力名，必须是 [架构方案](架构方案.md) 档位表里存在的；**写不存在的名字直接拒绝装载** |
| `impl.kind` | `shell`（走策略引擎，命中 `sh` 的规则）/ `http`（走域白名单）/ `script`（T1）/ `native`（T2） |
| `skills` | 正文**追加**进上下文，不占前缀，缓存安全 |
| `ui.slot` | `settings.section` / `result.renderer:<tool>` / `screen` —— 声明式，不给任意代码 |

## 三级的分界线

| | 能做什么 | 不能做什么 | 装载时的警告 |
|---|---|---|---|
| **T0 声明式** | shell 模板 + http 模板，参数来自 schema | 任何逻辑、循环、条件、状态 | 绿色：列出它要跑的确切命令模板 |
| **T1 脚本** | JS 里写逻辑，只能调 host 白名单绑定 | 直接读文件 / 直连网络 / 起进程 / 反射 | 黄色：列出它能调的每一个 host 函数 |
| **T2 原生** | 全能力 | —— | 红色：签名固定（首次装载时记 SHA-256），独立进程 + Binder |

**T1 的绑定表就是权限表。** 插件要读文件就得 `"capabilities": ["fs.read"]`，
host 才把 `host.fsRead()` 注进去；没声明就没有这个函数，不是"拦住"，是"不存在"。

## 和 MCP 的关系

MCP 不是第四级，它是**外援**：host 内置一个 MCP 客户端（DeepSeek 服务端不支持 MCP，
必须客户端自己把 MCP 的 tools 映射成 function tools），
连接方式写在配置里，接进来的工具与 `.dshp` 工具在模型眼里完全一样。

所以策略只有一条：**先接 MCP 拿生态，再攒自有 T0 工具。** 不要为了插件数量造生态。

## 一个真实的 T0 例子：电量历史

`tools/battery_history.json`

```json
{
  "type": "object",
  "properties": {
    "raw": { "type": "boolean", "description": "true 返回 dumpsys 原文，false 只返回摘要" }
  },
  "required": []
}
```

impl 是 `{ "kind": "shell", "command": "dumpsys battery" }`。
模型调用它 → 策略引擎发现 `shell.readonly` 在只读白名单 → 直接跑 → 结果回灌。

**注意 `raw` 这个字段**：默认摘要、要原文才给原文。
这就是"让工具做过滤"——手机上一个 `dumpsys` 动辄几千行，回灌原文等于每轮多花几千 token，
而缓存命中价 2% 也救不了"输出 token 单价是输入的 4 倍"这件事。
